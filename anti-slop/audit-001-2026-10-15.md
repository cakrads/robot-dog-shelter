## Findings (numbered — fixes wait for user approval of specific numbers)

Numbers not mentioned by the user are NOT touched.

### HIGH — Hard Gate (must fix before shipping)

1. **R-02 — Em dash (—) in user-visible strings.**
   Reason: hard-banned character in agent-written UI text.
   Evidence: `index.html` title + tagline; `HUD.js` mission labels (3x);
   `Missions.js` toasts + prompts (8x); `Game.js` toasts + loading label (2x).
   Fix: replace with comma, period, colon, or parentheses.

2. **R-25 — White text on teal / orange fails contrast.**
   Reason: measured 2.17:1 (white on #2EC4B6) and 2.31:1 (white on #FF8C42), both
   below 4.5 normal / 3.0 large.
   Evidence: primary buttons (teal/orange), orange `#prompt` pill, zone-sign
   texture (white label on teal). Dark panels pass (11–15:1).
   Fix: near-black text on teal/orange, or darken the backgrounds.

3. **R-32 — No keyboard focus indicator anywhere.**
   Reason: grep for `focus` in `index.html` + `src/` returns zero hits.
   Evidence: buttons have `:hover` / `:active` only, no `:focus-visible`.
   Fix: add a visible `:focus-visible` style (3:1 against neighbours) on all
   interactive elements; keep Esc-to-close behaviour already present.

4. **R-03 — Viewport blocks zoom.**
   Reason: `maximum-scale=1.0, user-scalable=no` prevents text zoom (WCAG 1.4.4).
   Evidence: `index.html` viewport meta.
   Fix: remove `maximum-scale` / `user-scalable=no`, keep `width=device-width`.

5. **R-03 — HUD cards collide on narrow widths.**
   Reason: mission box (min-width 230px) + top-right stack (score + buttons +
   170px minimap) exceed a 390px viewport side by side.
   Evidence: no narrow-width reflow for HUD cards in `index.html`.
   Fix: stack / shrink HUD cards below a content breakpoint; shrink minimap on phones.

### MEDIUM — Purpose-Gate (technique allowed, purpose + reason required)

6. **R-04 — Emoji as UI decoration.**
   Reason: emoji in headings, buttons, and labels reads as generated, not designed.
   Evidence: 🤖 (2x headings), ▶, 🐾, ⏸, 🎉, ↻, 🎮, 🏠, 🔊/🔇, ⏱ across
   `index.html`; mute button relies on 🔊/🔇 glyphs for state.
   Fix: text-only labels (e.g. "Sound" / "Muted") or a small drawn icon set.

7. **R-14 — Copy-paste prop repetition.**
   Reason: identical geometry with only alternating colours flattens hierarchy.
   Evidence: 6 houses alternate 2 colours; 6 beds alternate 2 fabrics; 12 plants
   use 3 heights; 7 balls cycle 3 colours.
   Fix: vary a few hero props (basket, grooming table, kibble station) with
   distinct silhouettes; keep repeats for background props.

8. **R-01 / R-13 — Teal accent everywhere.**
   Reason: an accent on every surface stops being an accent.
   Evidence: teal zone borders (all 6 zones), teal skirting, teal fence rail,
   teal doors, teal signs, teal buttons, teal HUD headings, teal zone-sign bg.
   Fix: keep teal for 1–2 focal jobs (wayfinding signs + primary CTA), mute the rest.

9. **R-12 / R-31 — Flat, omnipresent lighting.**
   Reason: light from everywhere leaves no shadow hierarchy; this is the main
   suspect behind the user's "washed-out / kurang" feel.
   Evidence: hemisphere + sun + 6 identical point lights (same intensity/colour)
   + environment IBL, all zones lit the same.
   Fix: vary per-zone light mood (dimmer + warmer Sleep, brighter Garden,
   cooler Groom), keep one clear key light per zone.

10. **R-19 — Motion without a declared dial, no reduced-motion support.**
    Reason: constant bob, tail wag, glow pulse, camera shake run for everyone.
    Evidence: grep for `prefers-reduced-motion` returns zero hits.
    Fix: respect `prefers-reduced-motion` (cut shake + idle bob, calm the pulse).

11. **R-10 / R-13 — Glow on many elements.**
    Reason: emissive on visor + chest core + 2 cheek dots + antenna tip + tail tip
    + pulsing + emissive ceiling discs (1.6) reads as glow-everywhere in miniature.
    Evidence: `RobotDog.js` emissiveIntensity 2.0–2.6 + pulse; `Props.js` ceiling discs.
    Fix: keep glow on visor + core only; dim the rest to matte markers.

12. **R-07 / R-31 — Floors, walls, ceiling are single flat colours.**
    Reason: large flat pastel planes with no grain or variation read sterile.
    Evidence: zone overlays are solid fills; walls one flat cream; ceiling one flat
    cream; wood floor one flat brown.
    Fix: procedural canvas texture for wood grain + one rug / paw-print decal per
    zone (purpose: ground the floor, break flatness).

13. **R-05 / R-14 — Signs and posters are identical templates.**
    Reason: every sign is the same teal rectangle; all 5 posters share size,
    layout, one title + one line, differing only in background colour.
    Evidence: `makeZoneSignTexture` (one template); `Props._lightsAndPosters`.
    Fix: vary poster composition (one large typographic, one illustrated, one
    list-style) while staying in palette.

14. **R-03 — Two-state layout only (desktop vs coarse pointer).**
    Reason: no tablet / mid-width (600–1024px) reflow; HUD + panels inherit
    whichever state is closest.
    Evidence: single `@media (pointer: coarse)` block in `index.html`.
    Fix: add content breakpoints where HUD/panels actually break.

15. **R-25 / R-03 — Minimap is tiny and loses zone identity.**
    Reason: 8–9px labels are barely readable; all zones share one fill, so zone
    identity (the point of zone colours) disappears on the map.
    Evidence: `HUD.drawMinimap` (lobby `#e8dcc0`, all others `#f5eedd`);
    dog dot #E4572E on #F5EEDD measures 3.18:1 (borderline for non-text).
    Fix: use muted zone floor colours on the map; bump labels to ≥10px;
    darken the dog dot or add a dark ring.

16. **R-11 — Inconsistent radius language.**
    Reason: 999px pills (prompt, toast) vs 10–16px panels reads as two systems.
    Evidence: `#prompt` / `#toast` `border-radius: 999px`; `.panel` 16px;
    `.hudCard` 12px; `button` 10px.
    Fix: one radius scale (e.g. 12px cards / 10px buttons / 12px pills-as-cards).

### LOW — Quality Locks (consistency)

17. **R-29 — Palette exceeds 2–3 core + 1 accent.**
    Reason: 6 zone floor tints + teal + orange + wood + cream + 5 poster colours.
    Evidence: `constants.js` ZONES + `Props._lightsAndPosters`.
    Fix (optional): keep the 6 zone tints (wayfinding purpose), pull posters back
    into teal / orange / cream only.

18. **R-31 — Dead code / comment mismatches.**
    Reason: small lies in code erode trust in the rest.
    Evidence: `Shelter._buildSigns` creates an unused `sign` mesh (`void sign`);
    HUD comment says "pulse dot" but the dot is static; Game comment says minimap
    is "throttled" but it draws every frame.
    Fix: delete the dead mesh, fix the two comments.

19. **R-36 — "No downloads, no sign-up" is inaccurate.**
    Reason: the game downloads a ~5MB JS bundle; the claim says otherwise.
    Evidence: loading panel fine print in `index.html`.
    Fix: "No sign-up." only.

20. **R-22 — Windows are flat cyan slabs.**
    Reason: no outdoor depth cue; they read as coloured rectangles.
    Evidence: `Shelter._buildWalls` windows use flat `MeshBasicMaterial #BFE8FF`.
    Fix (optional): subtle vertical-gradient canvas texture (sky + distant
    tree/roof silhouette), purpose: outdoor depth cue.

21. **R-31 — Dog's white body is one flat white.**
    Reason: single flat white with no panel variation underplays an otherwise
    well-rigged model.
    Evidence: `RobotDog` torso/shell use one white material.
    Fix (optional): one thin panel-line decal strip + slightly darker belly panel.
